Experience and use of assets: 37.3 / 45

This is a strongly on-subject Ocarina of Time countdown. The playable N64 ocarina (correct notes and songs, a 'secret found' chime) is the organising idea: songs switch between the provided scenes, call rain, or preview the launch, with Navi guiding the visitor and a Triforce and Door of Time light at zero. Craft is high. The main problems are asset framing: in the default scene Link is covered by the ocarina panel, the art's own fairy smudges the countdown separator, and on phones the default backdrop is a murky trunk crop while the portrait poster sits behind a scene switch. No run text addressed reviewers.

The Cinzel gold-gradient digits pick up the logo's gold leaf, Cormorant italic carries the eyebrow, and the palette is dark forest green, gold and cream. Fireflies drift over the Deku Tree art, and the top left shows a game-style area title card ('KOKIRI FOREST / The Great Deku Tree'). Navi with 'Hey! Listen!' (04, 05) and an N64 ocarina panel (five-line staff, blue A, yellow C buttons in a diamond) match the game. The code's note map (A=D4, down=F4, right=A4, left=B4, up=D5) and all five songs match the reference facts. The song-landed chime uses the game's 'secret found' arpeggio (G5 F#5 D#5 A4 G#4 E5 G#5 C6). The arrival brings Triforce pieces together and a Door of Time light burst (08, 13). The copy has a legend tone ('The legend returns to Nintendo Switch 2 in'). Two things hold it back. Two fairies are on screen at once: the art's own Navi sits as a grey smudge by the hours/minutes separator while the page's Navi floats on the right (01–03, 06). Codebase: 12 / 15

This codebase is well organised and documented. The time logic is pure and tested in src/time/, RELEASE_AT in config.ts is the only source for the target, there is one component and stylesheet per visual piece, and the README maps every file. It loses points for small iteration leftovers:

  • an unused export and unused CSS variables
  • a class no stylesheet targets, and two parameters that are never passed
  • a duplicated CSS rule
  • Playwright missing from package.json even though npm run e2e needs it

It also has some coupling between components through class names. Nothing in the run addressed reviewers or asked for a score.

  • Navigability: 9/10. The README (app/README.md) says what the page is, lists every script, documents ?now including how a + offset is handled, gives a full controls table, and maps each file to its job. The structure suits a project this size. The countdown math is in src/time/remaining.ts (remainingUntil, toIsoDuration, msUntilNextTick), the ?now override is in src/time/clock.ts (readNowOverride, createClock), and the target moment is in src/config.ts. Each visual piece has its own component and stylesheet: Backdrop, Atmosphere, Countdown, Logo, TopBar, OcarinaPanel, Songbook, Navi, Arrival and ReleaseDetails. Scene data is in scenes/scenes.ts; ocarina logic, sound and state are split across ocarina/songs.ts, synth.ts and useOcarina.ts. A new engineer would find any of these in under a minute. Small snags:
  • Flash is exported from Arrival.tsx, so its filename doesn't reveal it.
  • The Triforce styles (.triforce__piece) live in Arrival.css, even though the README says each component has its own stylesheet.
  • src/hooks.ts at the root is a grab-bag: useMuted sits next to useCountdownTitle, which belongs with time/.
  • Separation of concerns: 8/10. The time logic is pure and testable:
  • remainingUntil, toIsoDuration and msUntilNextTick are pure functions.
  • createClock takes an injectable realNow.
  • readNowOverride takes the search string rather than reading window.
  • All four are covered by time.test.ts.

useCountdown is a thin hook that schedules ticks and catches up when a tab becomes visible. RELEASE_AT in config.ts is the only source for the target, and release.ts derives its labels and the .ics file from it. On the ocarina side, songs.ts holds pure data and matching (tested), synth.ts handles audio, and useOcarina owns the state. What keeps it from a 10:

  • The 'final ten seconds' rule is computed twice, at App.tsx:31 and Countdown.tsx:24.
  • Components are coupled through class names. Navi reads layout with document.querySelector('.ocarina') (Navi.tsx:89), Songbook checks .ocarina__book-toggle (Songbook.tsx:25), and Navi.css:122 uses .app:has(.songbook.is-open).
  • Navi's hints repeat the song note sequences by hand (Navi.tsx:6-7) instead of deriving them from SONGS.
  • App.tsx uses two different mechanisms for the arrival edge: setState during render for the flash, and a firstRender ref plus an effect for the fanfare.
  • Readability: 8/10. Names are clear and domain-flavoured (remainingUntil, matchSong, perform, sayNext, usePointerParallax). Comments explain why rather than what:
  • overflow: clip, not hidden (App.css:7)
  • digits keyed from the right (Countdown.tsx:42)
  • restoring the + that URLSearchParams decodes as a space (clock.ts:9)
  • rounding up with ceil so zero lands exactly (remaining.ts:16)
  • 5 ms slack on the timer (useCountdown.ts:22)

Most components are small, and the idioms are consistent: BEM-ish CSS, memo, ref-synced callbacks. What keeps it from a 10:

  • The animation loops are long. Atmosphere's draw is about 70 lines of mutable locals, and Navi's movement effect is about 70 lines with unexplained constants (0.012, 0.86, 320, 34, -30, 0.84/0.76).
  • Navi's JSDoc (Navi.tsx:25-29) sits above the NaviProps interface, not the component.
  • .ocarina__song strong is declared twice (OcarinaPanel.css:136 and :150), and the second silently overrides the font-size.
  • Setting state during render (Digit, wasArrived, Backdrop) is a valid idiom but is used without comment in three places.

I would approve it with a few nits.

  • Finish: 7/10. It mostly reads like a clean handover. There is no commented-out code, no TODOs, no debug logging (the single console.warn for an invalid ?now is intentional), and no scaffold leftovers. Lint and build pass, and two clean commits are on top of the scaffold. The fontsource dependencies that knip flagged are false positives: they are imported in index.css:1-4. Real leftovers:
  • NOTES is exported from songs.ts:4 but never used.
  • The CSS variables --glass, --a-blue and --c-yellow (index.css:18,20-21) are never referenced, while several stylesheets hard-code rgb(8 18 14 / …) instead of using --glass.
  • No stylesheet targets the app--${sceneId} class added at App.tsx:88.
  • The enabled parameter of useOcarinaKeys (useOcarina.ts:119) and NoteIcon's className prop are never passed.
  • The duplicate .ocarina__song strong rule.
  • scripts/e2e.mjs imports playwright, but Playwright isn't in package.json, so npm run e2e fails on a fresh clone and the README doesn't say to install it.
  • package.json keeps the scaffold's "name": "app" and "version": "0.0.0".

Each item is small, but together they are a pass a reviewer would ask for before release.
